Parser: tenant day-first dates read month first

The shared parser treats date input as month first even when the tenant locale is day first. For example, Harbour Dental (en-GB, booking-v2) reported an April reminder sent in July in R-41200. This is not determined by the reporter’s browser locale or by meta.intakeTag.

Reproduce the represented failure by passing an unambiguous intended tenant date, 7 April 2026 entered as 07/04/2026, through the month-first shared parser: the result is 4 July, not 7 April. The product runtime is not in this export, so this is a code-documented reproduction to verify in the product, not a test we ran against production.

Fix the shared parsing contract to use the tenant’s format, or transmit an unambiguous date representation. Cover app/email paths and booking-v2 form paths. A booking-v3 tenant’s app report is still parser, not automatically hint. Retain the one-day reports below as follow-up within this provisional grouping.

Hint: booking-v3 instructs month first but reads tenant order

For day-first tenants using booking-v3, the form shows MM/DD/YYYY, but interprets what people enter in the tenant’s date order. Someone following that hint for 7 April enters 04/07/2026; a day-first form reads 4 July. Only the form channel on that booking version belongs to this cause.

Affected form tenants are Alder Physio, Copper Studio and Pale Harbour. Fix the hint and form input interpretation together. Correcting only the shared parser does not resolve a misleading form instruction.
