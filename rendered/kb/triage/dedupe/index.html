Triage: duplicate reports

owner support desk accepted reviewed 2026-10-28 · 0 days ago

A busy morning brings hundreds of reports about the same thing. We keep one ticket per issue and merge every duplicate into it, so engineering sees one thread with a count.

The rule

A report is a duplicate only when the evidence supports the same cause (decision 0002, superseding decision 0001):

  1. Read the body and look up the tenant locale and booking-form version.
  2. Compare the channel and cause with candidate tickets; use causeOf and sameCause for these date failures.
  3. Merge only with a verified same-cause ticket. Otherwise open a separate ticket or investigate if the cause is uncertain.
  4. Count unique report IDs and recompute totals when new exports arrive.
Subjects and browser intake tags help find candidates; neither proves a shared cause. The same subject can hide different bugs. A different subject can describe the same bug.

When you are unsure

Do not merge yet. Check the tenant directory and report body, then ask for missing reproduction evidence. An unknown tenant is not evidence that two reports share a cause. See the #4471 review for the split and its limits.
